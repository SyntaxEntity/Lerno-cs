# 408 资料写作规范

> 本文件是 `scripts/build.py` 的输入契约。作者（人或 Agent）只写 `parts/<科目>/<slug>.md`，
> **不得写考频数字、不得写模板字段标题**——这些由 `build.py` 从 `scripts/meta.py` 注入，
> 以保证 26 个知识点的模板与数据完全一致。

## 一、parts 文件格式（段落顺序固定，`#` 标题层级固定）

```markdown
# 核心讲解
（3—8 句。第一句直接给定义/结论；随后给关键公式、算法步骤、复杂度、成立前提。
 不铺垫背景、不写"同学们""我们知道"。公式与变量名一律用反引号包裹，如 `O(n log n)`、`next[i]`。）

# 关键结论速记
- `公式或结论` —— 一句话说明
（3—6 条）

# 示意图
（至少 1 个 ```text 的 ASCII 图 + 至少 1 个 ```mermaid 图，顺序不限，可交错）

# 易错点
- …（2—4 条，每条 30—80 字，必须写清"错在哪 + 正确是什么"）

# 真题示例
**20XX 年 408 第 N 题（选择题/综合应用题，X 分）**
（题干，含全部必要数据）
> 解析：（关键推导步骤 2—5 步 + 明确结论）
```

## 二、ASCII 图硬性约束（会被脚本校验，违反即报错）

1. **只能用**：ASCII 可见字符、空格、以及制表符集合
   `─ │ ┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼ ▲ ▼ → ← ↑ ↓`。
2. **禁止**全角字符：中文、`（）`、`：`、`、`、`，`、`×`、`≥`、`∈`、`√` 全部不得出现在代码块内。
3. 文字与外框间留至少 1 个空格；同一行内的 `│` 必须在同一列对齐。
4. 行宽建议 ≤ 74 字符，最长 ≤ 100 字符。
5. 图内只放**结构本身**（结点、指针、下标、数组槽位、位域）；解释性文字写在代码块外的正文。

## 三、Mermaid 图硬性约束

1. 必须能通过 mermaid v10 语法解析：只用 `flowchart TD/LR`、`stateDiagram-v2`、`graph`。
2. 节点 ID 用英文字母+数字（如 `A1`、`check`）；**中文一律放在 `[]`、`()`、`{}` 内**。
3. 节点文本内**不得**出现 `[` `]` `<` `>` `|` `"` `;` 等会破坏语法的字符。
4. 箭头标签只能写 `A -->|文字| B`。
5. **禁止** ASCII 箭头（`-->`）出现在节点文本里。

## 四、真题示例规范

1. 只能标注 **2009—2025** 年；题号必须落在本科目对应区间：
   - 数据结构：单选 1—10 题、综合 41—42 题
   - 计算机组成原理：单选 11—22 题、综合 43—44 题
   - 操作系统：单选 23—32 题、综合 45—46 题
   - 计算机网络：单选 33—40 题、综合 47 题
2. 优先使用真实真题。若使用改编题，必须写成「**20XX 年真题改编**」，禁止伪装成原题。
3. 解析写"关键推导"即可，不必抄写完整答案；必须给出**明确结论或数值**。

## 五、内容深度

- 面向"已系统学过、需要快速回想"的考生：给结论、给推导骨架、给对比表口径，不重复教材铺垫。
- 关键定义、公式、算法步骤必须与经典教材（严蔚敏《数据结构》、唐朔飞《计算机组成原理》、
  汤小丹《计算机操作系统》、谢希仁《计算机网络》）一致。
- 编造的定义、编造的真题、编造的公式 = 严重错误。
