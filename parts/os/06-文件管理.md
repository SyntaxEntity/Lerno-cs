# 核心讲解

文件管理把磁盘上的物理块抽象为按名访问的逻辑文件：文件逻辑结构分无结构流式（顺序文件）与有结构记录式（顺序、索引、索引顺序、散列），物理结构分连续、链接（隐式/显式 FAT）、索引（单级/多级/混合），其中 UNIX 混合索引的最大文件长度 = `D*a + I*a + I^2*a + I^3*a`，`D`、`I` 为直接与一级间接地址项个数，`a` 为盘块大小，逐项相加不得漏掉直接项。

**物理结构的对比**按"能否随机访问、有无外部碎片"两个口径看：**连续分配**支持随机访问且最快，但会产生**外部碎片**、文件不易动态增长、必须预先知道长度；**链接分配**用指针把盘块串成链，**隐式链接**把指针存在每个盘块里、只能顺序访问且任一处指针损坏就丢失后续内容，**显式链接**把指针集中到内存中的**文件分配表 FAT**（表项下标是块号、表项内容是下一块号），因而支持随机访问，代价是 FAT 要常驻内存；**索引分配**为每个文件建一个索引块、登记它的全部盘块号，支持随机访问且没有外部碎片，代价是索引块本身占空间，大文件还需多级或混合索引。

**FAT16** 每个表项占 16 位，故簇号上限为 `2^16 = 65536` 个（簇号 `0`、`1` 保留，实际可用约 `65534` 个），因此**最大分区 ≈ 簇数上限 × 簇大小**、**最大文件 ≈ 单文件可占簇数上限 × 簇大小**，例如簇大小取 `32 KB` 时两者都约为 `2 GB`；由此可知要扩大容量只能加大簇，而簇越大内部碎片越严重。

目录本质是文件名到 FCB 的映射表，采用索引结点（inode）后把文件名与除名字外的属性分离，目录项只留`文件名 + inode 号`，使检索时一个盘块能容纳更多目录项、显著减少 I/O 次数。文件共享靠硬链接（多个目录项指向同一 inode，`count` 计数，删除只减计数，为 0 才真正回收）与软链接（新建一个存放路径名的文件，删除原文件后软链接失效成为悬空链接）。

**虚拟文件系统 VFS** 在系统调用接口与各具体文件系统之间提供统一的抽象（`inode`、`dentry`、`file`、`super_block` 等对象与一组统一的 `open`/`read`/`write` 操作），使 `ext4`、`FAT`、`NFS` 等以同样的方式被访问；**挂载 `mount`** 把某个文件系统实例接到目录树中的一个**挂载点**上，此后访问该目录即进入被挂载文件系统的根目录，`umount` 则把挂载点摘除。

磁盘空间管理常用位示图、空闲链表、成组链接法；位示图的字号 `i`、位号 `j` 与块号换算按从 1 开始编号时为 `块号 = (i-1)*n + j`（`n` 为每字位数），从 0 开始编号时 `块号 = i*n + j`，两者必须与题设口径统一。进程访问文件先查进程打开文件表（含文件描述符、读写偏移、访问权限），表项指向系统打开文件表的全局表项（含 inode 指针、引用计数），再由 inode 逐级查目录与磁盘，最终由页/块缓存完成 `read`。

# 关键结论速记

- `最大文件长度 = D*a + I*a + I^2*a + I^3*a` —— 直接项与各级间接项都要乘盘块大小 `a`、间接项按层数取幂，每级可指块数 `= a / 地址项字节数`；漏乘 `a` 或漏掉直接项都会算小。
- `inode 把文件名与属性分离` —— 目录项只存`文件名 + inode 号`，检索路径名时目录占块少、命中率高，一个文件可被多个目录项共享。
- `硬链接 = 共享同一 inode + count++`；`软链接 = 新建文件存原路径` —— 删原文件后硬链接仍可访问数据，软链接变为悬空链接。
- `位示图 n 位/字` —— 从 1 开始编号 `块号 = (i-1)*n + j`；从 0 开始编号 `块号 = i*n + j`，`j` 为字内位号。
- `打开文件表两级` —— 进程表项（fd、读写位置、权限）唯一指向系统打开文件表项（inode 指针、引用计数），`read` 只改进程表项的偏移。
- `连续随机访问快但有外部碎片；隐式链接只能顺序访问，显式链接靠内存 FAT 支持随机访问；索引分配随机访问、无外部碎片` —— 索引块本身占空间是索引分配的代价。
- `FAT16：16 位表项 -> 簇数上限 2^16` —— 最大分区 ≈ 簇数上限 × 簇大小，最大文件也受可占簇数 × 簇大小限制，簇越大上限越高而内部碎片越多。
- `VFS 用统一的 inode/dentry/file 抽象屏蔽具体文件系统` —— `mount` 把文件系统挂到目录树的挂载点上，挂载不复制数据、也不改其内部结构。

**三种物理结构的串联方式与 FAT16 的上限**：连续分配的盘块在盘上相邻，链接分配靠指针串起，索引分配用索引块集中登记；指针放在盘块里只能顺序走，集中到内存 FAT 后才能随机跳。

# 易错点

- 算最大文件长度时漏掉直接地址项或漏乘盘块大小：正确做法是`直接项数*a + 一级间接项数*a + k*a + k^2*a + k^3*a`，`k` 由盘块大小除以地址项字节数得到，每一项都要乘 `a`。
- 把软链接说成共享 inode、或把挂载当成"把文件系统复制进当前目录"：软链接是独立文件、自身有 inode，内容只是原路径名，删原文件即悬空；`mount` 只是把另一个文件系统接到目录树的挂载点上，访问路径改由该文件系统解析，并不复制数据。
- 位示图块号与字号位号换算搞错起始编号：题设从 1 开始时`块号 = (i-1)*n + j`，从 0 开始时`块号 = i*n + j`，且同一题内字号、位号、块号必须同口径。
- 混淆链接分配的随机访问能力、并把 FAT16 的上限只归因于簇大小：隐式链接只能顺序访问，只有把指针集中到内存 FAT 的显式链接才支持随机访问；FAT16 的簇数上限由 16 位表项固定为 `2^16`，最大分区 ≈ 簇数上限 × 簇大小。

# 真题示例

**2010 年 408 第 46 题（综合应用题，8 分）**

某文件系统采用混合索引分配方式，inode 中有 10 个直接地址项、1 个一级间接地址项、1 个二级间接地址项、1 个三级间接地址项，每个地址项占 4B，磁盘块大小 4KB，则单个文件的最大长度是多少字节，约合多少 GB？

> 解析：每块可放指针数 `k = 4096 / 4 = 1024`。直接项可寻址 `10 * 4KB`；一级间接 `1024 * 4KB`；二级间接 `1024^2 * 4KB`；三级间接 `1024^3 * 4KB`。总和 = `(10 + 1024 + 1024^2 + 1024^3) * 4KB = (10 + 1024 + 1048576 + 1073741824) * 4096B ≈ 4.0001 * 10^12 B`，即约 `4TB`（若按 `1GB = 2^30 B` 计，约 `3725GB`；按 `10^9 B` 计约 `4000GB`）。结论：最大文件长度约 `4 * 10^12` 字节，数量级远大于按块号宽度直接相乘的粗算值，关键是三级间接项的高次幂且每项都乘盘块大小。
