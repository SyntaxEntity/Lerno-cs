### 为什么不能标「原题」

原型自己标的是「真题风格模拟」（144 题里 78 题有此标注），**从未声明是真题**。
按本仓库 `README.md` 第三节的口径，真题原题必须可核对（年份 · 题号），否则只能标
「改编」。所以本库一律：

```
"source": "改编",
"credit": "拾阶 408（授权）"
```

若将来确实收录可核对的原题，必须同时满足：`source: "原题"`、`origin`（如 `2021·第12题`）、
`README.md` 的已核对清单里出现该题、`F30` 校验通过——四件缺一不可。

## 三、字段

```json
{
  "id": "ds-01",
  "subject": "ds",
  "topic": "01-线性表",
  "stem": "题干……",
  "code": "可选的代码块",
  "options": ["A", "B", "C", "D"],
  "answer": 0,
  "explanation": "解析（≥15 字，说明为什么对/为什么错）",
  "source": "改编",
  "credit": "拾阶 408（授权）",
  "difficulty": 2,
  "tags": ["复杂度分析"]
}
```

约束（`validate.py` 的 **F30** 逐条强制）：

| 字段 | 规则 |
| --- | --- |
| `id` | `科目-序号`（如 `ds-01`），全局唯一 |
| `subject` | `ds` / `co` / `os` / `net`，须与所在文件一致 |
| `topic` | 必须是本仓库 26 个知识点之一（内容判据，不是文件名） |
| `options` | 2—4 项，非空、互不重复 |
| `answer` | 整数下标，`0 ≤ answer < len(options)` |
| `explanation` | 非空、≥ 15 字 |
| `source` | `原题` / `改编` / `自编` |
| `difficulty` | `1` / `2` / `3` |

## 五、映射方法（判据基于内容）

1. **以「考点」为单位定主题**：原型的 51 个考点是内容单元，按考点标题/摘要/要点

   对齐到本站的 26 个知识点（而不是按它 26 章的目录名硬映射——两边切法不同）；

2. **两个跨主题考点按题干细分**：
   - 顺序表/链表取舍：题干出现「链表/单链/双链」→ `02-顺序表与链表`，否则 `01-线性表`；
   - 线程与调度：题干出现「调度/周转/时间片/优先级…」→ `03-处理机调度与死锁`，否则 `02-进程与线程`；
3. **缺口按内容判定**：本站正文里根本没有 KMP / 冯·诺依曼等内容 → 进 `pending.json`；
4. **审计**：每条映射都计算「题干+解析」与目标章节正文的**字符二元组重合度**，

   记录在 `MAPPING.csv` 里，供人工复核。

## 六、改题库的正确姿势

```bash
# 1. 改 parts/quiz/*.json（或 pending.json）
# 2. 重新生成产物
python3 scripts/build_quiz.py
# 3. 校验（F30 源完整性 + F31 产物一致性）
python3 scripts/validate.py
```

常见错误与后果：

| 错误 | 谁会发现 |
| --- | --- |
| 答案下标越界 / 选项重复 / 解析过短 | F30 |
| `topic` 写了本站没有的知识点 | F30 |
| 改了源却忘记重跑 `build_quiz.py` | F31（源哈希 + 内容比对） |
| 手改了 `assets/quiz-data.js` | F31（4 项比对） |
| 删了某知识点的全部题目 | F30 警告（不阻断构建，但报告里看得见） |
