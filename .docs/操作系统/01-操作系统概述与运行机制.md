# 操作系统 · 操作系统概述与运行机制

## 操作系统概述与运行机制 [高频]

**考频统计**：考察次数 16 次；涉及年份：2009、2011、2013、2015、2017、2019、2021、2023、2024；分数占比约 10%；主要题型：选择题为主（内核态/用户态、系统调用、中断与异常）。

**核心讲解**：

操作系统是管理计算机硬件的系统软件，其四个基本特征是**并发、共享、虚拟、异步**，其中**并发与共享互为存在条件**（没有并发就无需共享，没有共享则并发程序无法推进）；虚拟建立在离散分配与多次性之上，异步是"程序走走停停、以不可预知的速度推进"。CPU 的执行状态分为**内核态**（管态）与**用户态**（目态）：只有内核态才能执行**特权指令**（如开关中断、设置时钟、清主存、修改 `PSW`、`I/O` 指令）并访问全部寄存器与存储空间；用户态只能执行非特权指令；`PSW` 的状态位标识当前处于哪一态，而**由用户态进入内核态的唯一途径是中断或异常**（系统调用本质上是通过**陷入指令 `trap`** 触发的一次特殊异常）。

注意 `trap` 指令本身**不是特权指令**——它需要在用户态执行才能完成"进入内核态"的动作。**中断**（外中断）来自 CPU 外部的事件（时钟中断、`I/O` 完成中断、控制台中断），**异常**（内中断）由当前执行的指令引起，分为故障 `fault`（如缺页、除零，可能被修复后重新执行该指令）、自陷 `trap`（如系统调用、断点，处理后返回到下一条指令）、终止 `abort`（如硬件故障，不返回）；**系统调用**的过程是：用户程序传递参数 → 执行陷入指令（`trap`/`syscall`，硬件将 `PSW` 改为内核态并转入内核入口）→ 内核按系统调用号查表执行服务例程 → 返回用户态。

操作系统内核通常包含**时钟管理、中断处理、原语、进程管理、存储管理、设备管理**等功能，**原语**是"执行期间不可中断"的原子操作，靠**关中断**实现；体系结构上，**宏内核**把所有功能放在内核态、效率高但可靠性差；**微内核**只把最基本的功能（进程调度、中断处理、消息传递）留在内核，其余移出为用户态服务进程，可靠性高但频繁的消息传递带来开销。

**操作系统引导**是上电后的第一件事：CPU 从复位向量执行固化在 ROM 或闪存中的 **BIOS/UEFI** 固件，完成 `POST` 自检与外设枚举后按启动顺序读取启动设备的**引导块**，再由**引导程序**（bootloader，如 `GRUB`）把内核映像装入内存并跳转到内核入口，内核建立页表、初始化各子系统后创建 1 号进程并启动 `shell`。

**虚拟机**由**虚拟机监控器**（`VMM`，Hypervisor）在物理硬件与客户操作系统之间虚拟出一套硬件，客户 OS 以为自己独占一台机器：**类型 1**（裸金属）的 `VMM` 直接运行在硬件上、本身相当于最底层的操作系统（如 `Xen`、`ESXi`），**类型 2**（寄居型）的 `VMM` 只是宿主 OS 上的一个应用程序（如 `VirtualBox`、`VMware Workstation`），其 `I/O` 要穿过宿主 OS，性能与隔离性都不如类型 1。

虚拟化的核心难点是**特权级**：客户 OS 被降级运行在非最高特权级上，它执行特权指令时会**陷入 `VMM`**、由 `VMM` 模拟执行后再返回（`trap-and-emulate`），对 x86 早期不可虚拟化的敏感指令则用**二进制翻译**，或修改客户 OS 改用 **`hypercall`**（半虚拟化）。

**关键结论速记**：

- `四个特征：并发、共享、虚拟、异步` —— 并发与共享互为存在条件，是最常考的相互关系。
- `特权指令只能在核心态执行；trap 指令是唯一能在用户态执行并进入核心态的指令` —— 把 `trap` 说成特权指令即为错误。
- `中断（外中断）来自 CPU 外部，异常（内中断）由当前指令引起` —— 时钟、`I/O` 完成属中断；缺页、除零、系统调用属异常。
- `fault 返回当前指令重新执行，trap 返回下一条指令，abort 不返回` —— 异常三分类的返回行为必须区分。
- `系统调用 = 传参 + 陷入指令 + 内核服务例程 + 返回用户态` —— 库函数不一定发生系统调用，系统调用一定进内核。
- `原语的原子性靠关中断保证` —— 关中断/开中断是特权指令，故原语只能在核心态运行。
- `引导链：BIOS/UEFI -> 引导程序 -> 装入内核 -> 内核初始化` —— 引导程序负责把内核映像装入内存并转交控制权，它本身不是内核的一部分。
- `类型 1 VMM 直接跑在硬件上，类型 2 VMM 是宿主 OS 上的应用` —— 客户 OS 的特权指令由 `VMM` 以陷入—模拟（`trap-and-emulate`）截获并代为执行。

**示意图**：

**用户态与内核态的地址空间与切换路径**：用户程序只能通过中断/异常这道"门"进入内核，内核通过修改 `PSW` 回到用户态。

```text
process address space and the user/kernel boundary

   high address
   +-----------------------------------+
   |          kernel space             |   only in kernel mode
   |  (kernel code, kernel stack,      |   privileged instructions allowed
   |   page tables, device drivers)    |   can access all memory
   +-----------------------------------+
   |     <-- boundary is enforced by hardware mode bit in PSW -->
   +-----------------------------------+
   |          user space               |   only in user mode
   |  stack  (grows downward)          |   non-privileged instructions
   |  ...                              |   cannot touch kernel space
   |  heap   (grows upward)            |
   |  data / bss                       |
   |  code (text)                      |
   +-----------------------------------+
   low address

mode switch paths

   user mode  --(1) system call via trap-->  kernel mode
   user mode  --(2) external interrupt   -->  kernel mode
   user mode  --(3) exception (page fault, divide by zero) --> kernel mode
   kernel mode --(4) return from trap/interrupt: restore PSW --> user mode
                 (returning to user mode is NOT a privileged-only act;
                  the OS does it by executing the return-from-trap instruction)
```

**从加电到第一个进程的引导链**：固件只负责自检与找到引导块，内核映像由引导程序装入内存，最后由内核把自己初始化成可运行的系统。

```text
boot chain: from power-on to the first user process

   power on / reset
   |
   v
   firmware: BIOS or UEFI in ROM      POST self test, device scan,
                                      follow the configured boot order
   |
   v
   read the boot block of the boot device
   |
   v
   bootloader (GRUB, Windows Boot)    in MBR or EFI partition; loads the
                                      kernel image, then jumps to entry
   |
   v
   kernel initialization              page tables, drivers, subsystems
   |
   v
   create pid 1 (init) -> shell -> user programs
```

**一次系统调用的完整流转**：参数通过寄存器或栈传递，`trap` 指令切换状态并跳转到内核固定的入口地址。

```mermaid
flowchart TD
    C0["用户程序调用库函数如 read"] --> C1["库函数把系统调用号放入寄存器"]
    C1 --> C2["参数放入约定的寄存器或压入用户栈"]
    C2 --> C3["执行陷入指令 trap 或 syscall"]
    C3 --> C4["硬件保存 PSW 与断点 切换到内核态"]
    C4 --> C5["按系统调用号查系统调用表"]
    C5 --> C6["执行内核服务例程 访问设备或文件系统"]
    C6 --> C7{"服务是否完成"}
    C7 -->|需要等待| C8["当前进程阻塞 调度其他进程"]
    C8 --> C6
    C7 -->|完成| C9["把返回值放入约定寄存器"]
    C9 --> C10["执行返回指令 恢复 PSW 回到用户态"]
    C10 --> C11["库函数返回 用户程序继续执行"]
```

**易错点**：

- 把 `trap`（陷入）指令当成特权指令，或认为用户态还有其他途径进入内核态：`trap` 必须在用户态执行才能完成"请求进入内核"的动作，属非特权指令；用户态进入内核只能经中断或异常，用跳转指令直接跳进内核代码会被特权级检查拒绝。
- 混淆中断与异常的分类归属：时钟中断、`I/O` 完成中断来自 CPU 外部，属**中断**；缺页、除零、系统调用、断点由当前指令引起，属**异常**；把缺页说成"中断"是最常见的概念错误。
- 混淆虚拟机类型 1 与类型 2：类型 1 的 `VMM` 直接运行在硬件上、本身充当最底层操作系统，类型 2 的 `VMM` 只是宿主 OS 上的一个应用；客户 OS 已被降级到非最高特权级，其特权指令会陷入 `VMM` 由它模拟执行。
- 把引导程序当成内核、或以为 BIOS/UEFI 自检后直接执行内核：BIOS/UEFI 只负责自检并按启动顺序读取引导块，真正把内核映像装入内存并跳转的是引导程序（如 `GRUB`），内核随后才做初始化并创建第一个进程。

**真题示例**：

**2011 年 408 第 23 题（单项选择题，2 分）**

下列选项中，在用户态执行的是（ ）。

A. 命令解释程序　B. 缺页处理程序　C. 进程调度程序　D. 时钟中断处理程序

> 解析：逐项判定所处的运行状态。**缺页处理程序**属于内存管理的内核功能，需访问页表与磁盘，必须在核心态（B 错）。**进程调度程序**要操作就绪队列与 `PCB`、修改 `PSW`，属内核功能，必须在核心态（C 错）。**时钟中断处理程序**是中断服务程序，由硬件中断触发、运行在核心态（D 错）。**命令解释程序**（`shell`）只是接收用户命令并创建子进程去执行，其自身运行在用户态，因此用户态可以执行（A 对）。答案选 **A**。**判分依据是"该程序是否需要访问内核数据结构或执行特权指令"，不需要即可在用户态运行。**
