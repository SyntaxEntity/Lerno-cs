核心讲解

逐个考点讲清

定点数的编码有四种：原码（最高位符号位，其余为绝对值）、反码（负数在原码基础上数值位取反）、补码（负数在反码基础上末位加 1）、移码（在补码基础上符号位取反，用于表示阶码）。n 位补码表示范围是 -2^(n-1) 到 2^(n-1)-1，比原码、反码多表示一个负数 -2^(n-1)，且 0 的表示唯一；n 位移码范围是 -2^(n-1) 到 2^(n-1)-1，其无符号数值大小顺序与真值顺序一致，所以移码适合做浮点数的阶码比较。

补码运算的溢出判断有两种等价方法：一是双符号位（变形补码）结果的两个符号位为 01 表示正溢出、10 表示负溢出；二是单符号位下判断"最高位进位 C_n 与次高位进位 C_(n-1) 是否异或为 1"。IEEE 754 单精度共 32 位，字段为 1 位符号 + 8 位阶码 + 23 位尾数，阶码用偏移量 127 的移码（E = e + 127），规格化数的尾数隐含最高位的 1（即 1.M），故真实有效位是 24 位。

特殊值约定：阶码全 0 且尾数全 0 表示 ±0；阶码全 0 而尾数非 0 表示非规格化数（此时隐含位为 0，用于表示接近 0 的数）；阶码全 1 且尾数全 0 表示 ±inf；阶码全 1 而尾数非 0 表示 NaN。浮点数加减的五个步骤是：对阶（小阶向大阶看齐，尾数右移，移出的位保留为保护位）、尾数加减、规格化（左规或右规，右规一次阶码加 1）、舍入（常用就近舍入即"0 舍 1 入"）、判溢出（阶码溢出才是真溢出，尾数溢出可用右规纠正）。C 语言中 int 到 float 的转换会因 float 只有 24 位有效位而丢失低位，float 转 int 是向零截断，这些都必须在位级上理解。

🔑

关键结论速记

考前扫读
  • n 位补码范围 [-2^(n-1), 2^(n-1)-1]、原码/反码范围 [-(2^(n-1)-1), 2^(n-1)-1] —— 补码比原码多一个负数，0 唯一。
  • 补码取负 = 全部位取反加 1；-128 的 8 位补码是 1000 0000 —— 该值没有对应的原码与反码。
  • 移码 = 补码的符号位取反、IEEE 754 阶码偏移量为 127（单精度）/ 1023（双精度） —— 偏移量与"移码"的常数不要混淆。
  • IEEE 754 单精度：1 + 8 + 23，隐含 1.M，真实有效位 24 位 —— 精度由尾数位数决定，范围由阶码位数决定。
  • 溢出判断：C_n 异或 C_(n-1)，或双符号位 01/10 —— 只有同号相加才可能溢出。
  • 浮点加减顺序：对阶 → 尾数运算 → 规格化 → 舍入 → 判溢出 —— 对阶一定"小阶向大阶看齐"。

易错点

踩过的坑
  • 混淆移码偏移量与 IEEE 754 偏移量：n 位纯移码是"补码符号位取反"（偏移 2^(n-1)），而 IEEE 754 单精度的阶码偏移量是 127（双精度 1023），两者不能互相代入。
  • 认为补码与原码表示范围相同：n 位补码比原码、反码多一个负数 -2^(n-1)，且 -2^(n-1) 不存在对应的原码与反码形式；此外补码的 0 表示唯一，原码与反码有 +0、-0 两种表示。
  • 把尾数溢出当成浮点溢出：尾数相加出现 1x.xxx 只是尾数溢出，可通过右规（尾数右移一位、阶码加 1）纠正；真正的溢出是阶码超出可表示范围，上溢才报错、下溢按机器零处理。
  • 对阶时方向搞反：必须小阶向大阶看齐（阶码小的数尾数右移），若反过来会让阶码变大而尾数左移，导致高位丢失、结果错误。

真题示例

自测用

2011 年 408 第 13 题（单项选择题，2 分）

float 型数据通常用 IEEE 754 单精度浮点格式表示。若编译器将 float 型变量 x 赋值为 -12.5，则该变量的机器数是（ ）。

A. 0xC1480000　B. 0xC1480001　C. 0xC1480002　D. 0xC1480003

解析：分三步。第一步，把 -12.5 化为二进制并规格化：12.5 = 1100.1B = 1.1001B * 2^3。第二步，填字段：符号位 S = 1（负数）；阶码 E = 真值阶 3 + 偏移 127 = 130 = 10000010B；尾数 M = 1001 后面补 0 到 23 位，即 10010000000000000000000。第三步，拼接并写成十六进制：1 10000010 10010000000000000000000 按 4 位分组为 1100 0001 0100 1000 0000 0000 0000 0000，即 0xC1480000。答案为 A。关键是把 -12.5 正确写成 1.1001B * 2^3，并把偏移量 127 加到真值阶上。

📖

核心讲解

逐个考点讲清

存储层次的依据是程序访问的局部性：越靠近 CPU 的层次越快、越小、越贵，Cache 与主存之间以块（行）为单位交换数据，主存与辅存之间以页为单位。Cache 的地址划分是本科目最高频的计算：把物理地址从低位到高位切成"块内地址（log2 块大小 位）→ 组号（log2 组数 位）→ 标记"三段。直接映射时"组"就是行，行号 = 主存块号 mod Cache 行数；N 路组相联时组数 = Cache 容量 / (块大小 × N)；全相联只有标记与块内地址两段。平均访问时间在"先查 Cache，未命中再访主存"的串行模型下为 T = 命中率 * Tc + 缺失率 * Tm；

若采用"并行/同时启动"或"流水"模型，公式中的 Tm 要改为"未命中时的额外开销"，必须按题意选择。Cache 行除数据外还需有效位，写回法还要脏位，替换算法用 LRU 时还要计数位或栈位，这些开销在做"Cache 总容量/总位数"题时必须计入。DRAM 需要定时刷新（一般取 2 ms 一个刷新周期），刷新按行进行、只需行地址，三种方式为集中刷新（有"死时间"）、分散刷新（无死区但存取周期变长）、异步刷新（折中，最常用）。

主存扩展分位扩展（数据线加宽，地址线共用）与字扩展（地址空间加大，需片选译码）。虚拟存储把逻辑地址翻译成物理地址：查 TLB → 查页表 → 若缺页则触发缺页异常；TLB 命中则不必访存取页表项，Cache 命中则不必访问主存，做时间计算时需按题意枚举四种命中组合。磁盘的存取时间 = 寻道时间 + 旋转延迟 + 传输时间，其中平均旋转延迟为旋转半圈的时间：60 / 转速 / 2。

🔑

关键结论速记

考前扫读
  • 组数 = Cache 容量 / (块大小 × 路数)，块内地址位数 = log2(块大小)、组号位数 = log2(组数)、标记位数 = 地址位数 - 组号 - 块内 —— Cache 地址划分三步走。
  • Cache 行总位数 = 标记 + 1 有效位 + 脏位(写回时) + 替换计数位 + 数据位 —— 做"总容量"题必须加控制位。
  • 串行模型 T = 命中率 × Tc + 缺失率 × Tm —— 若题中说明"并行访问"则需换成额外开销口径，不能硬套。
  • DRAM 刷新按行、以 2 ms 为周期、只需行地址 —— 集中/分散/异步三种方式的差别在"是否有死时间"。
  • 磁盘存取时间 = 寻道 + 旋转延迟 + 传输，平均旋转延迟 = 60 / (2 × 转速) 秒 —— 转速单位 rpm 换算成秒要除以 60。
  • TLB 命中 → 无需访存查页表；Cache 命中 → 无需访主存 —— 计算有效访问时间时必须按题意枚举命中组合。

易错点

踩过的坑
  • 缓存容量计算漏掉控制位：Cache 行除数据块外还有有效位（写回法还有脏位、LRU 还有计数位），题目问"Cache 总位数/标记阵列容量"时必须加上这些位，只算数据位会偏小。
  • 把"组数"与"行数"混用：直接映射时组数等于行数，而 N 路组相联时 行数 = 组数 × N；若把组数直接当行数去算组号位数，地址划分会整体错位。
  • 用错平均访问时间模型：T = h·Tc + (1-h)·Tm 只适用于"先查 Cache 再访主存"的串行模型；若题目说"Cache 与主存同时启动"或给出"未命中额外开销"，必须改用对应公式。
  • 旋转延迟算成一圈：平均旋转延迟是半圈时间，即 60 / (2 × 转速) 秒（转速为 rpm）；算成一圈会使结果翻倍，磁盘存取时间题必错。

假设某计算机按字节编址，主存地址为 32 位，采用 8 路组相联映射的 Cache，Cache 数据区容量为 512 KB，每个主存块大小为 64 字节，Cache 采用写回法并含 LRU 替换所需的计数位。要求：给出物理地址中标记、组号与块内地址的位数；求 Cache 中每一行的总位数（含必要的控制位）。

核心讲解

逐个考点讲清

一条指令由操作码字段与地址码字段构成。定长指令字中操作码位数固定，可表示 2^k 条指令；变长指令字中常用扩展操作码技术：把操作码按长度分层，短操作码不能再作为长操作码的前缀，因此设计时必须保证"短码不是任何长码的前缀"。以 4 位为基础操作码、需要扩展到 8 位为例，若 4 位编码 0000—1110 分配给 15 条三地址指令，则剩下 1111 作为扩展标志可产生 16 个 8 位编码，用于二地址指令，依此类推。寻址方式决定操作数的来源与有效地址 EA 的计算：立即寻址的地址字段就是操作数本身；直接寻址 EA = A；间接寻址 EA = (A)（需访存两次取数，三次含取指）；

寄存器寻址的操作数在寄存器中，不访存；寄存器间接寻址 EA = (R)；相对寻址 EA = (PC) + A，其中 PC 已是取下一条指令后的值（即已自增）；基址寻址 EA = (BR) + A，基址寄存器由操作系统设定、面向整个程序，用于程序重定位；

变址寻址 EA = (IX) + A，变址寄存器由用户改变、面向数组，用于数组元素的顺序访问；堆栈寻址的操作数隐含在栈顶。CISC 与 RISC 的分野在于：RISC 采用定长指令字、指令条数少且格式规整、只有 Load/Store 访存、通用寄存器多、采用硬布线控制与流水线，而 CISC 指令变长、寻址方式多、以微程序控制为主。汇编层面必须能读懂"取数—运算—存数"的三段式，重点掌握 mov、add/sub、cmp 与条件转移 jmp/jcc、以及 push/pop 对栈指针的改变。

关键结论速记

考前扫读
  • 扩展操作码约束：短码不得是长码的前缀 —— 否则译码时无法判断指令长度。
  • 相对寻址 EA = (PC) + A，PC 已自增到下一条指令 —— 这是 408 反复考查的细节，忘记自增会整体偏移。
  • 基址寻址面向程序重定位（基址寄存器由 OS 设定），变址寻址面向数组（变址寄存器由用户改变） —— 两者形式相同、用途不同。
  • 一次间接寻址取操作数需访存 2 次（含取指共 3 次） —— 访存次数是间接寻址的标志性代价。
  • RISC：定长指令 + 只有 Load/Store 访存 + 多通用寄存器 + 硬布线 + 流水线 —— 与 CISC 的对比是固定选择题考点。

易错点

踩过的坑
  • 相对寻址忘记 PC 已自增：EA = (PC) + A 中的 PC 是"取下本条指令后已加一个指令长度"的值；若直接用本条指令地址去加偏移量，结果会整体偏差一条指令的长度。
  • 基址与变址寻址的用途互换：基址寻址的基址寄存器内容由操作系统给出、程序执行中不变，用于程序浮动/重定位；变址寻址的变址值由用户改变，用于数组或字符串的顺序访问。
  • 扩展操作码设计违反前缀约束：把 1111 同时用作一条 4 位指令又用作 8 位扩展标志，译码器无法判定指令长度；正确做法是把该编码只留给扩展。
  • 认为指令字长必须等于机器字长：指令字长可以等于、小于或大于机器字长（半字长、双字长指令都常见），只要求是字节的整数倍（按字节编址时），取指所需访存次数由指令字长与存储字长共同决定。

某计算机采用定长指令字，指令字长 16 位，采用扩展操作码方式。若三地址指令有 12 条、二地址指令有 20 条，则一地址指令最多有（ ）条。

解析：设操作码基础长度为 4 位，三地址指令需要 12 个编码，占 0000—1011；剩余 1100、1101、1110、1111 共 4 个编码可作扩展标志。每个扩展标志可扩展出 4 位（地址字段让出 4 位），即每个标志下可得到 2^4 = 16 个 8 位编码，故二地址指令编码空间为 4 × 16 = 64 个。二地址指令实际用了 20 条，剩余 64 - 20 = 44 个 8 位编码可继续作扩展标志，每个再扩展 4 位得到 2^4 = 16 个 12 位编码，故一地址指令最多 44 × 16 = 704 条。关键是逐层计算"剩余编码数 × 每级扩展倍数"，且绝不能把已用的编码再当扩展标志。

核心讲解

逐个考点讲清

CPU 由运算器（ALU、暂存寄存器、通用寄存器组、PSW）与控制器（PC、IR、ID、时序电路、微操作信号发生器）组成，其核心工作是按 PC → IR 取指、译码、执行、访存、写回的顺序，在数据通路中把一串微操作按时序节拍展开。取指周期的微操作序列固定为 (PC) -> MAR、M(MAR) -> MDR、(MDR) -> IR、(PC) + 1 -> PC，此后译码器根据 IR 中的操作码产生后续控制信号。数据通路按总线数目分为单总线与多总线结构：单总线结构每拍只能有一个数据流入/流出总线，完成一次 ALU 运算需 取操作数1 → 暂存 → 取操作数2 → 运算 → 写回 多拍；多总线（如双总线、三总线）可在一拍内同时传送两个操作数，微操作序列更短。控制器分硬布线与微程序两类：硬布线由组合逻辑直接产生微命令，速度快、不易修改，RISC 常用；

微程序把微命令编成微指令存于控制存储器 CM，一条机器指令对应一段微程序，CM 容量 = 微指令条数 × 微指令字长。微指令编码方式中，水平型微指令并行能力强、字长长、微程序短，垂直型微指令一次只能完成一个微操作、字长短、微程序长，字段直接编码法与字段间接编码法用于压缩互斥微命令。流水线把指令执行划分为 k 个阶段，理想情况下 n 条指令需 k + n - 1 个时钟周期，吞吐率 TP = n / ((k + n - 1) * T)，最大吞吐率 TP_max = 1 / T（T 为最长阶段耗时，即流水线周期）。流水线存在结构冒险（资源冲突）、数据冒险（RAW 为主）、控制冒险（转移指令）三类；数据冒险可用转发（旁路）解决，但 load-use 必须暂停一拍，控制冒险可用分支预测、延迟槽、提前形成转移地址解决，冒险会使实际加速比与效率低于理想值。

🔑

关键结论速记

考前扫读
  • 流水线周期 T = max(各阶段耗时) —— 取最长阶段而非平均值，瓶颈段决定节拍。
  • TP = n / ((k + n - 1) * T)，TP_max = 1 / T —— k 是流水段数，n 是指令条数，两者不可混用。
  • S = 串行时间 / 流水时间 = (n * k * T) / ((k + n - 1) * T) = n * k / (k + n - 1) —— 理想加速比上限为 k。
  • E = S / k = n / (k + n - 1) —— 效率等于各段设备的时空利用率，理想值为 1。
  • CM 容量 = 微指令条数 × 微指令字长 —— 微程序控制器容量计算，与机器指令条数无直接相等关系。
  • load-use 冒险必须暂停 1 拍 —— 转发只能解决 ALU 结果相关，无法把访存结果提前到上一拍。

核心讲解

逐个考点讲清

总线是连接多个部件的共享传输介质，按功能分为数据总线（双向，位数决定一次能传多少位）、地址总线（单向，由 CPU 指向主存/IO，位数决定寻址空间）、控制总线（双向/单向混合，传时序与命令）。按层次分为片内总线、系统总线（含数据/地址/控制三类）、通信总线。

性能指标中最常考的是带宽：总线带宽 = 总线工作频率 × (总线宽度 / 8) 字节/秒，若一个总线周期能传送多个数据字，则还要乘上每周期传送的次数；总线传输周期 = 一个地址 + 一个数据字的传送时间，含地址期与数据期，若题中给出"每个总线周期含 k 个时钟"，则带宽 = 总线宽度 / (k × 时钟周期)。总线仲裁解决多个主设备争用总线的问题，三种方式的特点必须分清：链式查询只需 3 根线（请求、允许、忙），结构简单、扩充容易，但优先级固定且离控制器越近越高，且某一环节故障会导致其后所有设备无法获得总线；

计数器定时查询用一组设备地址线代替允许线，优先级可通过计数初值改变、较为灵活，但增加 log2 n 根线；独立请求每个设备都有独立的请求线与允许线，响应最快、优先级最灵活，但线数最多（2n 根），控制逻辑最复杂。总线定时决定数据传送的时序：同步定时由统一时钟控制，速度快、协议简单，但各设备必须在同一时钟节拍内完成，适合速度相近的设备；异步定时用"请求—应答"握手，分为不互锁（请求方不等回答即撤销）、半互锁（请求方等回答，回答方不等请求撤销）、全互锁（双方都等对方撤销），可靠性高但速度慢；半同步在同步基础上加一条 WAIT 线以兼容慢速设备。

关键结论速记

考前扫读
  • 总线带宽 = 工作频率 × 总线宽度 / 8（字节/秒） —— 宽度按字节折算，位/秒 则不必除以 8，单位不能混。
  • 带宽也可写为 总线宽度 / 总线传输周期 —— 当题目给出"每个总线周期含 k 个时钟"时用此式更稳。
  • 链式查询 3 根线、优先级固定；独立请求 2n 根线、优先级最灵活 —— 线数与灵活性的权衡是选择题核心。
  • 同步定时靠统一时钟，异步定时靠握手（不互锁/半互锁/全互锁） —— 异步更适合速度差异大的设备。
  • 地址总线位数决定寻址空间：n 位可寻址 2^n 个单元 —— 与数据总线宽度决定的"一次传送位数"不要混淆。
  • 总线复用：同一组线在不同时间段传地址与数据 —— 复用可减少引脚数，代价是速度下降。

易错点

踩过的坑
  • 总线带宽计算漏乘或单位错：总线宽度以位给出时要先除以 8 换算成字节，带宽结果单位是 B/s；若题目问 b/s 则不要除。另外当一个总线周期含 k 个时钟时，必须除以整个周期而不是单个时钟。
  • 认为链式查询的优先级可以自由设置：链式查询的优先级由设备在链上的物理位置决定，离总线控制器越近优先级越高，无法通过软件随意改变；要改变优先级需用计数器定时查询方式。
  • 把地址总线位数与数据总线位数的作用弄反：地址总线位数决定可寻址的主存单元个数（n 位对应 2^n 个单元），数据总线位数决定一次能并行传送的位数，两者互不相干。
  • 混淆异步定时的三种互锁方式：不互锁是请求方不等应答就撤销请求（最快但最不可靠），半互锁是请求方等应答、应答方不等请求撤销，全互锁是双方互相等待（最可靠但最慢）；把半互锁与全互锁的等待关系写反是常见失分点。

真题示例

自测用

2015 年真题改编（单项选择题，2 分）

某同步总线的时钟频率为 100 MHz，总线宽度为 32 位，地址/数据线复用，每传送一个地址或一个数据都占一个时钟周期。该总线支持突发传送方式，一次突发连续传送 8 个数据字（只需送出首地址一次）。则这次突发传送的数据传输率约为（ ）。

A. 356 MB/s　B. 400 MB/s　C. 800 MB/s　D. 3200 MB/s

解析：地址/数据线复用意味着一个总线周期至少要占"地址期 + 数据期"。突发传送只送一次首地址，随后连续送 8 个数据字，故一次突发共需 1 + 8 = 9 个时钟周期，传送数据量为 8 × 32 位 = 32 字节。时钟周期 = 1 / 100 MHz = 10 ns，9 个时钟耗时 90 ns，故数据传输率 = 32 B / 90 ns ≈ 0.356 × 10^9 B/s ≈ 356 MB/s，答案为 A。若忘记计入地址期（只算 8 个时钟）就会得到 400 MB/s 的干扰项 B——"地址/数据线复用 + 突发传送"必须计入一次地址期开销，这是本题的判分点。

核心讲解

逐个考点讲清

I/O 接口（设备控制器）的作用是数据缓冲、格式转换、状态与命令寄存、地址译码，它把 CPU 的高速并行总线与设备的低速串行工作方式解耦。I/O 端口的编址有两种：统一编址（把端口当作主存单元，用普通访存指令访问，无需专门指令但占用主存地址空间）与独立编址（有独立的地址空间与专用 IN/OUT 指令，不占主存空间但指令类型增多）。I/O 控制方式的发展主线是CPU 干预程度逐步降低：程序查询方式下 CPU 不断读状态寄存器空转等待，CPU 与设备完全串行；

程序中断方式下 CPU 发出命令后继续执行原程序，设备就绪时用中断通知 CPU 在一条指令执行结束后响应，数据传送仍需 CPU 用指令搬入主存；DMA 方式由 DMA 控制器直接在主存与设备之间成块传送，数据不经过 CPU 的寄存器，每传送一个字（或一个数据块）占用一次总线（周期挪用/周期窃取），只有在传送前（初始化）与传送后（中断处理）才需要 CPU 参与；通道方式由通道处理器执行通道程序，进一步把 CPU 从 I/O 管理中解放出来。

中断系统要点：CPU 响应中断的条件是"有中断请求 + 中断允许触发器为 1 + 当前指令执行结束"；响应时由硬件自动执行中断隐指令完成三件事——关中断、保存断点（PC）、取中断向量；随后由中断服务程序保存现场并执行服务。

多重中断（中断嵌套）靠中断屏蔽字控制：屏蔽字中某位为 1 表示屏蔽（禁止）对应的中断源，因此优先级越高的中断源，其屏蔽字中"1"的位数越多。磁盘的性能指标是存取时间，存取时间 = 寻道时间 + 旋转延迟 + 传输时间，其中平均旋转延迟为旋转半圈的时间 60 / (2 × 转速)（转速单位 rpm）；数据传输率与位密度、转速（线速度）相关，数据传输率 = 每条磁道的容量 / 旋转一圈的时间。固态硬盘 SSD 基于闪存，无机械寻道与旋转延迟，随机访问快，但存在写放大、擦除次数受限（寿命）的问题。

关键结论速记

考前扫读
  • 四种 I/O 方式 CPU 干预程度：程序查询 > 程序中断 > DMA > 通道 —— 判据是"CPU 是否需要在传送过程中持续参与"。
  • DMA 数据不经过 CPU 寄存器，直接在主存与设备间传送 —— 这是 DMA 与程序中断方式的本质区别。
  • 中断隐指令由硬件执行：关中断、保存断点、取中断向量 —— 它是"指令"但不是程序里的指令。
  • 中断响应时机：一条指令执行结束后 —— 而不是任意时刻，也不是一个时钟周期后。
  • 屏蔽字为 1 表示屏蔽，优先级越高屏蔽的位数越多 —— 多重中断靠它实现嵌套。
  • 磁盘存取时间 = 寻道 + 旋转延迟 + 传输，平均旋转延迟 = 60 / (2 × 转速) 秒 —— 旋转延迟取半圈。

易错点

踩过的坑
  • 认为 DMA 传送完全不需要 CPU 参与：DMA 只在数据传送过程中不需要 CPU 干预，传送前的初始化（设置主存地址、设备地址、传送长度、方向）与传送结束后的中断处理都必须由 CPU 完成。
  • 把中断响应时机写成"任意时刻"或"一个时钟周期后"：可屏蔽中断只在一条指令执行结束后响应（这样断点才是一条指令的边界）；若在指令中间响应，断点无法正确保存。
  • 混淆中断隐指令与中断服务程序：中断隐指令是硬件自动执行的（关中断、保存断点、取中断向量），而保存现场、执行设备服务、恢复现场是中断服务程序（软件）做的，两者不能混为一谈。
  • 磁盘旋转延迟算成一圈：平均旋转延迟是旋转半圈的时间，即 60 / (2 × 转速) 秒；若按一圈计算，存取时间会偏大一倍。

真题示例

自测用

2012 年真题改编（单项选择题，2 分）

某磁盘的转速为 7200 rpm，平均寻道时间为 8 ms，数据传输率为 20 MB/s。若读取一个 4 KB 的磁盘块，则平均存取时间约为（ ）。

A. 4.2 ms　B. 8.2 ms　C. 12.4 ms　D. 16.5 ms

解析：平均存取时间由三段相加。平均旋转延迟 = 60 / (2 × 7200) s = 4.17 ms（旋转半圈）；传输时间 = 4 KB / 20 MB/s = 4096 B / (20 × 10^6 B/s) ≈ 0.205 ms；再加上平均寻道时间 8 ms，得 8 + 4.17 + 0.205 ≈ 12.37 ms，最接近 C。干扰项 D（16.5 ms）正是把旋转延迟误算成一整圈（8.33 ms）的结果，B（8.2 ms）则是完全漏算旋转延迟的结果。判分点是旋转延迟必须取半圈，以及单位换算（rpm 转秒要除以 60、KB 与 MB 统一为字节）。
